# UR5 实机联调步骤

1. 确认物理急停、安全平面和限位已经现场验收，工作区无人。
2. 运行 `scripts/verify_environment.py`，确认 Python、Spinnaker CTI 和依赖正常。
3. 当前两个标定 YAML 已保留用户确认的真实结果；联调前复核分辨率、相机/镜头和末端安装均未变动，不得用单位阵或临时数值覆盖。
4. UR5 设置为 `192.168.0.10`，活动 TCP 必须六维精确为零。
5. 按界面编号操作：相机预览 → UR5 只读 → 系统检查 → 干运行 → 联调档 → 使能 → 开始跟随。
   “使能”阶段会清空干运行状态，重新等待授权后 RTDE 样本和 10 个真实稳定视觉帧；
   在此过程完成前“开始跟随”不得生效。
6. 首次只使用联调档（50 mm/s）。确认跟随方向、包络和停车正确后，才允许进入试验档。

> 软件停车不能代替 UR 物理急停和现场风险评估。

## 第一阶段只读性能采样（不发送运动）

在低性能电脑上正式干运行/使能之前，先关闭 SpinView 和视觉伺服界面，在工程根目录执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\run_read_only_performance_probe.py --duration-s 60
```

脚本只启动相机、UR5 `RTDEReceive` 和视觉处理线程，不调用干运行、实机使能、`servoL` 或
任何控制接口。结束后会打印新的 `experiment_logs/<会话目录>`。随后执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\analyze_performance_log.py `
  .\experiment_logs\<会话目录>
```

把该会话目录中的下列文件一起回传，不能只截界面图片：

- `FULL_ASYNC` 模式下的 `performance_stages.csv` 与 `performance_stages.meta.json`，或 `LIGHT` 模式下的 `performance_summary.csv`
- `performance_stage_summary.csv` 与 `performance_analysis_summary.json`
- `timing.csv`、`vision.csv`、`robot_state.csv`、`session_manifest.json`

采样期间保持固定 ID 标签完整可见，先静止 30 秒，再用手缓慢平移标签 30 秒。性能分析不要求
也不允许机器人运动。若探针报错，也保留整个会话目录；不要放宽 EKF、100 ms 延迟或时间戳门限。
