# 实验电脑部署与测试

## 1. 拷贝与一键环境

1. 整体拷贝 `visual_servo_system` 文件夹，不拷贝另一台电脑生成的 `.venv` 和 `.python311`。
2. 右键 PowerShell 或在文件夹中打开终端，运行 `./安装相机驱动.ps1`。脚本会显式请求管理员权限。
3. 运行 `./一键离线安装.ps1`。它仅使用工程内 Python 3.11 嵌入式运行时和锁定 wheel，不联网。
4. 运行环境检查：

```powershell
.\.venv\python.exe .\scripts\verify_environment.py
```

## 2. 上机前必须检查

- `calibration_files/camera_intrinsics.yaml` 的分辨率为 1280×1024，且与相机输出一致。
- `calibration_files/hand_eye_eye_in_hand.yaml` 中的 `T_flange_camera` 仍对应当前物理安装。
- `config_files/camera_settings.yaml` 中序列号为 16276663。
- `config_files/robot_connection.yaml` 中地址与 UR5 当前 IP 一致，活动 TCP 必须为六维精确零值。
- UR 示教器处于可接受外部控制的正常安全状态，现场物理急停可用。

## 3. 分步测试命令

### 纯离线，没有任何运动接口

```powershell
.\.venv\python.exe .\scripts\run_offline_validation.py
.\.venv\python.exe .\scripts\benchmark_diagnostics_modes.py --cycles 2000
```

### 相机单独只读

```powershell
.\.venv\python.exe .\scripts\test_camera_read_only.py --frames 300
```

若有以前保存的 1280×1024 图像文件夹，可运行与生产一致的 0.5 倍搜索+原图角点/PnP：

```powershell
.\.venv\python.exe .\scripts\run_image_folder_replay.py `
  .\offline_images --output-directory .\runtime_data\image_replay `
  --fps 30 --performance-mode FULL_ASYNC
```

### UR 状态单独只读

```powershell
.\.venv\python.exe .\scripts\test_ur_state_read_only.py --samples 1250
```

该脚本只导入 `rtde_receive`，不构造 `RTDEControlInterface`。输出必须审查 accepted、duplicate、delayed、out_of_order、clock_reset 和 missed_deadlines。

### 相机 + RTDE + 视觉只读性能探针

```powershell
.\.venv\python.exe .\scripts\run_read_only_performance_probe.py `
  --duration-s 60 --performance-mode FULL_ASYNC
```

此脚本不执行干运行、实机选择、使能或 `servoL`。完成后对会话目录执行：

```powershell
.\.venv\python.exe .\scripts\analyze_performance_log.py `
  .\experiment_logs\<会话目录>
```

## 4. 日志模式

修改 `config_files/diagnostics_settings.yaml` 的 `performance_mode`：

- `"OFF"`：正常联调默认，不启动性能写者。
- `"LIGHT"`：异步聚合并输出周期汇总，适合长时间只读观察。
- `"FULL_ASYNC"`：输出详细阶段 CSV，仅用于专项性能测试。

注意 YAML 1.1 会把未加引号的 `OFF` 解析为布尔值，因此必须保留双引号。

## 5. 正式程序操作顺序

```powershell
.\启动视觉伺服.ps1
```

界面操作必须严格按：连接相机/预览 → 连接 UR5 只读状态 → 系统检查 → 干运行 → 选择限速档和后端 → 使能 → 开始跟随。
在新的 60 s 只读探针和低速分步联调未通过前，不得选择实机后端。

## 6. 回退

修复前的原始基线已上传到 `https://github.com/xuxianghu214-wq/visual_servo_system.git`，基线提交为 `dda7997`。回退时不要在正在运行的工程上覆盖：

1. 关闭程序并确认 UR 已停车。
2. 将当前整个文件夹改名保留实验日志。
3. 从 GitHub 的 `dda7997` 下载新文件夹。
4. 把已复核标定 YAML 复制到对应路径，重新运行一键离线安装。
