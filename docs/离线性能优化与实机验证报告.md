# UR5 视觉伺服性能优化与离线验证报告

## 1. 结论

已在不连接 Point Grey 相机和 UR5 的开发电脑上完成代码修复与离线回归。本次最明确的性能根因已确认：旧
`PerformanceProfiler.record()` 虽然把 CSV 放到消费线程，但每条阶段记录仍在生产线程同步重写
`.meta.json`。视觉帧又连续提交多条阶段记录，因此穿透了“异步日志”设计，造成实测约 46.16 ms 未归因开销。

新实现已取消生产线程写元数据，将一帧/一个 RTDE 样本的多阶段合并为一次 `put_nowait`，通过有界队列批量写盘。
队列满时只丢弃普通诊断并统计，安全事件仍使用独立通道。

RTDE 时间映射已分类 `accepted / duplicate / delayed / out_of_order / reset`。重复包和乱序旧包不再进入拟合、不重置映射、
不增加状态序号且不发布到最新状态缓存。读取循环超期时从当前时刻重建节拍，不使用零等待连续轮询“追赶”旧 deadline。

## 2. 已知实机基线（修复前）

- 相机 30.007 FPS，视觉 11.923 FPS。
- 视觉总耗时平均 79.58 ms，P95 95.94 ms；可见算法平均 33.43 ms。
- 旧诊断记录额外平均约 46.16 ms；7 条阶段提交平均 14.89 ms，P95 27.12 ms。
- RTDE 记录 77.29 Hz，4651 个样本只有 4 个映射可靠，60 s 重置 662 次。
- 相机时间戳可靠率 58.69%，不确定度 P50/P95 为 19.67/31.67 ms。

上述值只是修复前的静态 AprilTag 硬件数据，不能用于证明动态跟踪或闭环稳定性。

## 4. 时钟回放和故障注入

- 模拟 125 Hz：125/125 accepted，0 reset。
- 模拟 77 Hz：77/77 accepted，0 reset。
- 混合异常 50 包：38 accepted、2 duplicate、1 out-of-order、8 delayed、1 true reset；映射器只重置 1 次。
- 相机断连、RTDE 中断、旧帧积压、时间映射失效、EKF 超时、非法标定、日志溢出和工作线程异常全部闭锁故障，
  控制接口构造数和运动命令数均为 0。

## 5. 24.1 ms 不确定度的含义

现有映射只有“设备采样时钟”和“主机收到数据时钟”的单向样本。算法使用最小排队边界估计偏移，输出的 uncertainty 是观测窗口内
相对该边界的最大附加延迟，而不是可以与外部真值比较的绝对时钟误差。旧数据中约 24.1 ms 主要反映 USB/网络排队、Python 线程调度、
驱动缓冲以及旧同步诊断 I/O 共同引起的到达时延散布。仅靠单向 RTDE 或相机帧无法把这些项唯一分解，因此代码不会输出伪精确的绝对误差。

## 6. 实机闭环准入状态

### 已通过离线验证

- 三种诊断模式、有界队列、溢出计数、批量关闭和写者故障隔离。
- RTDE 重复/延迟/乱序/真实重置分类，重复包不发布。
- 30/77/125 Hz 模拟回放、丢帧、延迟、抖动、漂移、重复和重置。
- 所有离线故障场景不构造实机控制接口。

### 代码完成、待实验电脑验证

- Blackfly S 硬件时间戳字段是否在 Spinnaker 4.4.0.246 + GenTL 中持续有效。
- CB3 PolyScope 3.7.2 对 125 Hz 请求的实际协商/输出频率，以及重复包比例。
- OFF/LIGHT/FULL_ASYNC 下的相机 FPS、视觉 FPS、P95/P99、CPU、内存和时间可靠率。
- 静态 10 mm/2° 与动态 20 mm/5° 精度。

### 当前仍阻塞实机闭环的条件

在实验电脑新的只读探针未证明相机与机器人时间映射长时间稳定、端到端延迟满足 100 ms 且重复时钟不再引发无意义重置前，
不满足实机闭环准入条件。不得放宽 20 ms 时间门限、伪造时间戳或重用旧观测。
