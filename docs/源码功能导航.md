## 相机和标志观测的安全语义

相机连接时先加载厂家 `UserSet Default`，再按 `CameraSettings` 设置像素格式、宽、高和帧率；
存在的 GenApi 节点必须回读一致。BFS-U3-13Y3C 是彩色型号，`Mono8` 会强制 ISP 2x
binning，因此工程固定使用 `BayerRG8` 保持 1280×1024，并由 OpenCV 转为 BGR。由于某些
相机不公开这些可写节点，每帧还会独立核对实际宽高；不符合标定分辨率的帧会报错，不会流入 PnP。
只有明确列入白名单的 RGB/BGR/Bayer 原生格式才能降级运行，降级状态会出现在
`pixel_format_fallback`、`status_message` 和帧质量中。

相机设备时钟映射的不确定度门限单独由 `camera_settings.yaml` 的
`timestamp_max_uncertainty_s` 配置；实机USB测试值为20 ms。RTDE继续使用更严格的默认门限，
两者互不影响。

`MarkerPoseObservation.pixel_area_px2` 是像素平方单位的标志面积；OpenCV ArUco
不提供 decision margin，因此 `decision_margin` 为 `None`，两者不可混用。
`marker_settings.yaml` 的 `detection_scale` 只控制标签搜索图的缩放比例，默认 0.5；检测角点会
换算回原始 1280×1024 像素坐标并在原灰度图上做亚像素精修，PnP 始终使用原标定内参和原图
畸变参数。因此它不是相机分辨率，也不能据此改写 `camera_intrinsics.yaml`。
连续丢失达到配置帧数或时间后，检测器会清除旧连续性锚点以允许固定 ID 重获；
重新使能或人工切换试验时可显式调用 `reset_tracking()`。单帧大跳变仍会被拒绝。

## TCP 零值授信与阻塞线程

`ur_rtde 1.6.5` 的 `RTDEReceiveInterface` 没有 `getTCPOffset()`。所以只读连接刚建立时，
`actual_TCP_pose` 绝不能直接冒充法兰位姿：状态样本会标为无效且不会进入法兰历史。控制接口
只有用户完成干运行、选择实机并点击使能后，才会建立控制连接并执行
`sender.authorize_state_reader(reader)`。这个 API 会真实读取控制接口的
`getTCPOffset()`、严格检查六维零值，并把读取器登记到发送器的撤销链；`sender.stop()`、TCP
读取失败、门禁失败、`servoL` 或 `waitPeriod` 异常都会自动撤销，调用方不再依赖手写撤销顺序。

相机优先使用 GenTL buffer 的设备曝光时间，RTDE 优先使用控制器 `getTimestamp()`；两者都由
`DeviceClockMapper` 映射到同一个主机单调时钟。数据包同时保留接收时刻、来源、可靠性和不确定度。
没有设备时间、样本不足或残差过大时，只允许预览/干运行，实机选择与使能门禁都会拒绝。
重复控制器时间戳不会重置映射或发布新状态，小回退按乱序计数，只有超过重置回跳量的时基改变才开始新映射代次。
延迟始终从映射后的采样/曝光时刻计算，不用接收完成时刻低估通信延迟。

每次实机使能都建立新的授权代次：先清空干运行的 EKF/预测/MPC/插值/稳定计数，
记录授权前状态序号，确认 TCP=0 后清空法兰历史，只接收序号更新且采样/接收时刻都不早于授权的样本。
`RobotPoseHistory` 的插值结果继承两端时间来源，不确定度包含端点值与采样间隔界；
任一端不可靠或插值不确定度超过门限时，该图像不得进入 EKF 或稳定计数。

`UrRtdeServoSender.stop()` 负责幂等停车；生产运行链外层使用
`DeferredUrRtdeServoSender`，其 `stop()` 会立即按 `disconnect()` 语义释放底层对象。
故障人工确认并重新使能时，factory 必须创建新的控制对象并重新授权 TCP，
不会复用已停车的对象。
`sender.disconnect()` 会先尽力执行 `servoStop()` 和 `stopScript()`，再显式调用底层
`disconnect()` 释放控制连接。用 `with UrRtdeServoSender(...)` 时，离开作用域按
`disconnect()` 语义收尾。并发停车入口不等待可能阻塞的厂商连接调用；
它会递增停车代次，连接返回后的使能流程发现代次已变就会放弃使能并释放对象。

相机与 RTDE getter 位于厂商 C 扩展，Python 无法保证从另一线程安全中断。RTDE 使用独立的
last-success 看门狗，超时会先把系统置为故障；若 `stop()` 等待后工作线程仍存活，会抛出
`CameraShutdownTimeout` 或 `RobotShutdownTimeout`，并故意保留底层资源。上层收到该异常必须
停车，不能并发 `destroy()` / `disconnect()`；等工作线程自行返回后再次调用 `stop()` 完成释放。

## EKF、预测和控制坐标链

`TargetPoseEkf` 的协方差顺序固定为：位置误差、SO(3) 右乘姿态误差、线速度、目标局部角速度，
各三维。非零角速度预测会用 SO(3) 雅可比旋转姿态误差协方差，姿态校正后还会执行误差重置。
视觉观测按图像时间戳配对法兰位姿，再通过
`T_base_marker = T_base_flange · T_flange_camera · T_camera_marker` 进入 EKF。姿态创新使用
SO(3) 对数映射；六维马氏距离超过 99% 门限时只保留预测，不把跳变写进状态。
在 `VALIDATED`（尚未运动）状态，若相邻视觉观测超过 EKF 的最大传播间隔，运行器会丢弃过时
估计、预测、MPC 和稳定计数，并用当前有效观测建立新 EKF 代次；这使低性能电脑不会因单次
慢帧永久失去预览。`ENABLED`、`FOLLOWING` 或遮挡衰减状态不会执行该恢复，异常仍进入统一
故障停车路径。

遮挡期间，预测器按“距最后观测的累计时间”采用指数速度衰减
`v(t)=v0·exp(-t/τ)`，相应位移为
`v0·τ·(1-exp(-t/τ))`。当前估计的 3σ 位置/姿态不确定性超过 30 mm/5°，或距最近观测
达到 1 秒时，预测轨迹立即标为无效。3σ 使用 3×3 协方差块最大特征值对应的最坏方向，
不会漏掉相关项造成的高不确定性。正常可见时使用常速度轨迹；未来一秒尚未发生的协方差
增长不会被误当成当前故障，当前不确定性由 EKF 按实际流逝时间传播。

目标位姿转法兰目标的闭环等式是
`T_base_marker = T_base_flange_desired · T_flange_camera · T_camera_marker_desired`，所以
`T_base_flange_desired = T_base_marker · inverse(T_camera_marker_desired) · inverse(T_flange_camera)`。
MPC 的位姿误差、角速度和角加速度统一在 base/spatial 坐标表达。它以 20 Hz 更新，优化六维
加速度并约束线/角向量二范数；OSQP 内部使用球内接保守盒，求解后再逐步精确复核整条控制和
状态轨迹。求解器异常、不可行、非严格 `solved`、超时或任一非有限量都返回零速度无效结果，
不切换控制器。最终运动还须通过安全状态机与 RTDE 发送门两层检查。

生产运行器的唯一链路是：相机最新帧 → 固定 ID 标志检测 → 按图像主机时间插值法兰位姿 →
三矩阵坐标变换 → EKF → 1 秒预测 → 法兰目标构造 → 20 Hz MPC → 安全门 → 位姿插值 →
125 Hz `servoL`。各线程之间使用容量恒为 1 的 `LatestValueBuffer`，慢消费者只会取得最新值，
不会积压旧帧或旧控制目标。界面通过定时器读取同一批只读快照，不参与控制循环。

安全状态机的停止和故障均锁存。正常数据恢复不会自动重新运动；人工确认后状态只回到预览，
还必须重新完成系统检查、连续 10 帧稳定目标、档位选择和使能。MPC 与安全限值分别来自
`mpc_controller.yaml` 和 `safety_limits.yaml`，角度配置在 YAML 中用度表示，进入算法边界时转弧度。

## 标定安全门

精确路径如下：

1. `calibration_files/camera_intrinsics.yaml`
2. `calibration_files/hand_eye_eye_in_hand.yaml`

当前便携工程中的两个文件已是用户确认的真实标定，`calibration_complete: true`。严禁用单位阵或伪造数值绕过检查。
任何相机、镜头、焦距、图像分辨率或末端安装关系变化都使当前标定失效，必须重新标定。

`T_flange_camera` 的语义不可调换：parent=`flange`、child=`camera_optical`，用于
`p_flange = T_flange_camera @ p_camera`，平移为米。相机运行分辨率还必须与内参标定分辨率
完全一致。

## 运行配置

`config_files/` 下七个 YAML 分别描述相机、标志物、机器人连接、伺服目标、MPC、安全限制和性能诊断。
加载入口 `load_system_config()` 返回显式不可变 dataclass，不把未经校验的字典传进控制链。
