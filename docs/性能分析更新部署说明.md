# 性能分析更新部署说明（历史版）

> 该文件记录第一阶段性能探针的历史部署方法。当前版本请以
> `docs/实验电脑部署与测试.md` 为准；性能诊断默认为 OFF，只有 FULL_ASYNC
> 才会生成详细 `performance_stages.csv`。

本更新只增加纳秒级计时、异步性能日志、只读采样脚本和汇总脚本。它不调整 MPC、EKF、
时间同步、安全阈值或 UR5 运动命令。

## 在运行视觉伺服的电脑上更新

1. 关闭视觉伺服程序和 SpinView。
2. 备份原电脑上的整个 `visual_servo_system`，尤其是 `calibration_files` 和 `experiment_logs`。
3. 把更新包内的文件夹按原目录层级复制到工程根目录，允许覆盖同名源码；更新包不包含
   `calibration_files`，不会替换实机标定。
4. 保留原电脑已有的 `.venv`。统一启动脚本和两个性能脚本都会从工程 `src` 加载最新源码，
   因此依赖版本未改变时不必重装 Python 环境。
5. 运行静态环境检查：

```powershell
.\.venv\Scripts\python.exe .\scripts\verify_environment.py
```

## 采集60秒只读性能数据

确保相机和 UR5 网线已连接、UR5 已开机，但不要启动视觉伺服界面。执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\run_read_only_performance_probe.py --duration-s 60
```

该脚本不会执行干运行、实机使能、`servoL` 或控制接口连接。前30秒保持 AprilTag 静止且完整
可见，后30秒用手缓慢移动标签。脚本结束后会打印本次会话目录。

## 自动汇总

```powershell
.\.venv\Scripts\python.exe .\scripts\analyze_performance_log.py `
  .\experiment_logs\<脚本打印的会话目录名>
```

把整个会话目录复制回来。至少必须包含：

- `performance_stages.csv`
- `performance_stages.meta.json`
- `performance_stage_summary.csv`
- `performance_analysis_summary.json`
- `performance_analysis.md`
- `timing.csv`
- `vision.csv`
- `robot_state.csv`
- `session_manifest.json`

如果探针失败，也不要删除会话目录或放宽门限；把报错文字和现有日志一起带回分析。
